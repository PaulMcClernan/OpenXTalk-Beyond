- Android engine: the engine and the externals an Android standalone can include are built from this tree with a current NDK (r30: Clang, the LLVM tools and lld, Android 5.0 and later, 16 KB pages on 64-bit) for arm64, armv7, x86_64 and x86, and checked as Android and the builder take them, by the new "Android engine" workflow (tools/ci/build-android.sh, tools/ci/android_engine.py). They are build artifacts only: packages still ship LiveCode 9.6.3's Android engine. config.py and the prebuilt libraries' scripts use the NDK's own toolchain only when there is no standalone toolchain, which builds as before (#402)
- libffi: its ARMv7 assembly writes five VFP loads and stores in the unified syntax, the same instructions, so that the NDK's Clang assembles it as GNU as did (thirdparty/libffi/ORIGIN); a test assembles every libffi assembly file each Android architecture builds (#402)
- Android engine: what the NDK's current Clang and headers refuse, and NDK r15's took, is fixed without changing what is built: libffi's x86 ffi_call_SYSV is declared with the type its callers pass (thirdparty/libffi/ORIGIN), libFoundation and HarfBuzz's ICU code ask for C++17 again after Android's own settings (ICU 78's headers need it, as on the web), an Android dialog returns false rather than nil, and two files include the POSIX headers of what they use; tests check each (#402)
- Android engine: the Java layer's four AIDL interfaces (in-app purchases) are compiled from the Java kept beside their .aidl files, LiveCode's own aidl output, as the Java layer's check already builds them, instead of being regenerated by the SDK's aidl, whose current versions refuse the build's paths and write other Java; the classes are those LiveCode 9.6.3 shipped (#402)
- Skia: on 32-bit ARM, SkFixedMul is the portable 64-bit product rather than inline assembly that a current Clang refuses (its operands could put both halves of the product in one register, which ARM leaves unpredictable); the result is the same for every input, as upstream Skia has it (thirdparty/libskia/ORIGIN) (#402)
- Android engine: everything an Android build compiles, the libraries it links included, is position-independent code (-fPIC), as a Linux build's is and as shared libraries need; the NDK's Clang makes PIE code by default, which its linker refuses there (#402)
- Android engine: on 32-bit Android, libFoundation's file streams use the 32-bit fseeko and ftello that Android 5 and 6 have, as the shipped engine's build did; the NDK's current headers declare neither when 64-bit offsets are asked for below Android 7.0 (#402)
- Android engine: with a current NDK every library links the C++ library into itself and asks for no shared one; the gyp settings and ICU's link flags no longer add -lstdc++ there, which named the NDK's libc++_shared.so, a library Android does not have. A standalone toolchain's link flags are unchanged (#402)
- Android engine: the Java layer serves both Android engines: OpenGLView.start(), which LiveCode 9.6.3's engine calls, makes the OpenGL ES 1 context it always made, and the new startGLES(int) makes the OpenGL ES 3 context an engine built from this tree draws in, which that engine asks for; the Java layer's check reads which each engine calls and holds it against the OpenGL ES library the engine loads (#402)
