- Android engine: the engine and the externals an Android standalone can include are built from this tree with a current NDK (r30: Clang, the LLVM tools and lld, Android 5.0 and later, 16 KB pages on 64-bit) for arm64, armv7, x86_64 and x86, and checked as Android and the builder take them, by the new "Android engine" workflow (tools/ci/build-android.sh, tools/ci/android_engine.py). They are build artifacts only: packages still ship LiveCode 9.6.3's Android engine. config.py and the prebuilt libraries' scripts use the NDK's own toolchain only when there is no standalone toolchain, which builds as before (#402)
- libffi: its ARMv7 assembly writes five VFP loads and stores in the unified syntax, the same instructions, so that the NDK's Clang assembles it as GNU as did (thirdparty/libffi/ORIGIN); a test assembles every libffi assembly file each Android architecture builds (#402)
- Android engine: what the NDK's current Clang and headers refuse, and NDK r15's took, is fixed without changing what is built: libffi's x86 ffi_call_SYSV is declared with the type its callers pass (thirdparty/libffi/ORIGIN), libFoundation and HarfBuzz's ICU code ask for C++17 again after Android's own settings (ICU 78's headers need it, as on the web), an Android dialog returns false rather than nil, and two files include the POSIX headers of what they use; tests check each (#402)
