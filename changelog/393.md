- Android: standalones carry the Android runtime's Java layer built from OXT-Beyond's source (from the next runtimes asset on; the Android engines are still LiveCode 9.6.3's). On Android 12 and newer mobileCreateLocalNotification schedules the notification and answers its id instead of nothing (run on Android 13 and 15 emulators), and NFC tag dispatch no longer fails there (checked in the code, not on a device). Two of LiveCode's later fixes come with it: keyboardActivated and keyboardDeactivated are sent when the keyboard shows or hides, not at the next event, and another app that reads a file the app shares (mobileComposeMail's attachments) without naming columns gets every column instead of an error (#393)
- Runtimes asset: make_runtimes_asset.py --android-classes puts the Java layer built from the asset's commit in place of the carried Runtime/Android/Classes, once it holds the layer's classes and every PendingIntent says whether it is mutable; the "Runtimes asset" workflow builds it and checks it as android-java.yml checks a pull request's (compare with the pinned asset's, jni, rules) before the archive takes it. The manifest entry names it (java_layer), PROVENANCE.md says what it replaced, package.py --compare lets that one file differ from 1.15's, and runtimes_provenance.py counts the commits for it (#393)
