- HyperCard import: rule T44 puts in quotes an object's name that this engine reads as one of its constants ("show cd fld help", "hide btn arrow", "add 1 to fld Plus"). HyperCard had no such constants and took the word as the name; here those lines compiled and named another object (field 15, button 29, field 13). This changes scripts that compile too (#239)
- HyperCard import: rule T45 takes HyperCard's Home stack named but not gone to ("set the script of stack "Home" to tScript", "send GetHomeInfo to Stack Home") to the HyperCard Library's new hcHome(): HyperCard's Home if it was imported and is open, else a stand-in stack "HyperCard Home" whose behavior is the library. Before, "stack "Home"" was the IDE's own home stack, whose script an imported installer replaced. Handlers installed into the stand-in are reached by a send to Home, not by every stack as in HyperCard, and the stand-in passes startUp on as HyperCard's Home did (#239)
- HyperCard import: rule T11 no longer turns the operator "is in" after a card or stack into "is of" ("if the short name of this cd is in cd fld "Index""), a line that did not compile: 21 handlers in 7 stacks of the corpus were left out for it. Rule T2 now renames a variable that is the last word before a \ that continues the line ("or menu \", a doMenu handler's parameter), which left 4 handlers out (#239)
