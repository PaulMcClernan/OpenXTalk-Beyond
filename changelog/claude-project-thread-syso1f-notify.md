- Android: a "Post Notifications" box among the Application Permissions of the Android standalone settings. Android 13 and newer show an app's notifications only once the user allows it: with the box ticked, the app asks the user the first time in a run that mobileCreateLocalNotification schedules one, so that the notification shows. An app without it is never asked, as before, and the notification is scheduled either way (needs the Java layer built from OXT-Beyond's source, which the runtimes asset carries from its next release; run on an Android 13 emulator by the Android builder workflow). androidRequestPermission answers false, instead of stopping the app, when Android answers its request with no result (#PR)
- IDE stack patches: a clone patch adds a copy of a control to a binary IDE stack (its name, unique id and own properties), verified as the other patches are: the copy is its source but for what the patch sets, the objects above it moved up a layer, and nothing else changed (tools/oxt/ide-stack-patch.livecodescript; check_ide_stacks.py reads them) (#PR)
- Android builder check: android_check.py device --allow <permission> waits for Android's dialog asking for a runtime permission, taps Allow and checks that the package holds it; the Java layer's probe declares POST_NOTIFICATIONS and must ask for it on the Android 13 and 16 KB emulators (#PR)
