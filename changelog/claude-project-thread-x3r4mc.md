- Engine: `the microseconds` (also `the long microseconds`, and the names microsecs, microsecond and microsec), the microseconds since 1970, as HyperXTalk has it: to the microsecond on macOS and Linux, and finer on Windows 8 and later; its names are not reserved words, so a variable, handler, parameter or custom property named microseconds works as before, and `the microseconds of me` is still a custom property (#215)
- Engine: the `matches wildcard` and `matches regex` operator, as HyperXTalk has it: `tName matches wildcard "*.txt"` is true when the pattern, read as the filter command reads one, matches the whole name, and `tText matches regex tPattern` is true when matchText would be; `matches` is not a reserved word, so a variable, handler or custom property named matches works as before (#215)
- Extensions: the HyperXTalk Compatibility library (org.openxtalk.library.hxtcompat), with HyperXTalk's `iff(condition, valueIfTrue, valueIfFalse)`, `quotedPrintableEncode` and `quotedPrintableDecode` (RFC 2045, with lines of at most 76 characters) and `microseconds()`, as handlers that come after a script's own handlers of the same names, which are called as before (#215)
- Script Editor: Comment and Uncomment in the right-click menu, as in the Edit menu (from HyperXTalk) (#215)
- Engine: a handler, a `do` script or a `value` expression that compiled before compiles as it did, every line of it: one is read with `the microseconds` and the `matches` operator only if it does not compile without them, so a line that already meant something else means what it did (`get tText matches wildcard (tPattern)` is still `get tText`, then a call of a handler named matches, and `beep the microseconds` a beep, then a call of a handler named the), and a script that compiles neither way reports the error it reported before; so do a server script's handlers and its lines outside them (#215)
- Engine: a `merge` template's `[[...]]` or `<?...?>`, or a parameter of `send` given as text, that does not compile without `the microseconds` or the `matches` operator was left as text before, and is now worked out, as when any function is added (#215)
