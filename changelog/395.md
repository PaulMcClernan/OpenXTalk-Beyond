- Android: the Java layer is ready for apps that target API 35 and 36. On Android 16, which sends such an app's back button and gesture only to a back callback, the stack still gets backKey (and the busy indicator still closes, as before); on Android 15 and newer, which draw such an app edge to edge, the stack is kept out of the status and navigation bars, the display's cutout and the keyboard (when it resizes the window, as by default), so it has the area it had. Apps that target API 33, as the builder makes them today, are unchanged (needs the Java layer built from OXT-Beyond's source, which the runtimes asset carries from its next release) (#395)
- Android standalone builder: a package targets API 36, which Google Play asks of new apps and updates, when the Android runtime's Java layer is ready for it, and API 33, as before, when it is not (LiveCode 9.6.3's layer, which the runtimes asset carries until its next release). At 36 the manifest keeps the stack's orientation and size on large screens as before (PROPERTY_COMPAT_ALLOW_RESTRICTED_RESIZABILITY, which Android 16 heeds until an app targets 37). A stack can pin the target with its "android,target sdk" standalone setting, from 33 to 36; any other value stops the build with an error (#395)
- Android builder check: android_check.py verify --target <api> checks the API the packages target, and at 36 the large-screen property (below 36, that it is not there); device --back presses the back key once the probe is green, and the Java layer's probe's backKey must turn it blue; device --within-bars checks that the stack is not drawn under the status and navigation bars. The workflow's Java layer's probe targets 36 and is run with both, on Android 13 and on a 16 KB image at API 36 or newer (Android 16), and the other packages with --within-bars (#395)
