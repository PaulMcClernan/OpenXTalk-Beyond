- Android standalones: an app no longer closes when the user changes the font size, bold text or the language, attaches a keyboard, or resizes its window. Android made the app's screen again for those in the same process, and Android 11 and newer stopped the engine as it started a second time there. The builder's manifest now lets the app go on through them (android:configChanges: LiveCode's four as before, then smallestScreenSize, screenLayout, fontScale, fontWeightAdjustment, locale, layoutDirection, keyboard, navigation, touchscreen, colorMode, mcc and mnc; not density), with any runtime. On Android 10 and older, where those changes started the stack again, it now goes on as on newer Android (#405)
- Android Java layer: with this checkout's layer (a later release's runtime), for a change no manifest can list (the display size, the theme overlays Android 12 and newer make of the wallpaper) the app starts again in a new process instead of closing (com.runrev.android.RelaunchActivity, which the builder declares in a process of its own only where the runtime's Java layer has it); and once the stack quits (as an unhandled backKey quits it) the app's process ends, so that the app opened again starts in a new process instead of closing (#405)
- Android builder check: device --font-scale (the app goes on in its process through a font size change), --density (it starts again in a new process for a density change) and --relaunch (once its stack quits, its process ends and the app opened again starts in a new one), each failing on a crash or an fdsan line in the device's log; verify checks the activity's configuration changes and that the manifest declares RelaunchActivity exactly when the package's dex has it; compare expects the new configuration changes. The workflow builds the app probe with this Java layer and runs it with all three on both emulators, the packages with the release's layer with --font-scale, and records that layer across a density change and opened again (#405)
- Android Java layer check: jni says of a jar without a class that the builder names only where the jar has it (RelaunchActivity, so a release's jar) that it lacks it, and no longer fails on it; with --every-named, as the workflow runs it on the jar built from this checkout, every class the builder names is still asked of the jar (#405)
