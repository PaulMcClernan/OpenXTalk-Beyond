- Android: a "Post Notifications" box among the Application Permissions of the Android standalone settings. Android 13 and newer show an app's notifications only once the user allows it: with the box ticked, the app asks the user the first time in a run that mobileCreateLocalNotification schedules one, so that the notification shows. An app without it is never asked, as before, and the notification is scheduled either way (needs the Java layer built from OXT-Beyond's source, which the runtimes asset carries from its next release; run on an Android 13 emulator by the Android builder workflow). androidRequestPermission answers false, instead of stopping the app, when Android answers its request with no result (#394)
- IDE stack patches: a clone patch adds a copy of a control to a binary IDE stack (its name, unique id and own properties), verified as the other patches are: the copy is its source but for what the patch sets, the objects above it moved up a layer, and nothing else changed (tools/oxt/ide-stack-patch.livecodescript; check_ide_stacks.py reads them) (#394)
- Android builder check: android_check.py device --allow <permission> waits for Android's dialog asking for a runtime permission, taps Allow and checks that the package holds it; the Java layer's probe declares POST_NOTIFICATIONS and must ask for it on the Android 13 and 16 KB emulators (#394)
- Android: mobileExportImageToAlbum adds the picture to the Pictures folder through Android's media store on Android 10 and newer, as Android asks there. Writing the file failed on Android 10, and on Android 11 and newer when another app's picture had the name (Android now names the new one apart); a picture of that name that the app saved before is replaced, as before, and Android 9 and older write the file as before. On Android 13 and newer, which refuse the Write External Storage permission without asking and grant an app nothing by it, it counts as granted for an app that ticks "Write External Storage", so specialFolderPath("external documents") and ("external cache") and mobileExportImageToAlbum work there; androidHasPermission and androidRequestPermission answer true for it there, where they answered false (needs the Java layer built from OXT-Beyond's source, which the runtimes asset carries from its next release; checked on the Android 13 and 16 KB emulators by the Android builder workflow) (#394)
- Android builder check: the Java layer's probe also asks for its external folder and WRITE_EXTERNAL_STORAGE and exports a picture to the album, takes every step and says what each answered in the device's log; android_check.py device prints what it said, and --picture <name> checks that the picture is among the shared pictures as the package's own (#394)
