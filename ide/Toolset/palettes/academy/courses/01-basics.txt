unit: First steps
icon: footprints

Say hello, do sums, join words, and learn to read code.

lesson: Hello, xTalk
id: hello
minutes: 5

A program is a list of instructions that a computer follows, one after another, from the top. In xTalk each instruction is called a **statement**, and each statement goes on a line of its own.

The first word you will learn is `put`. On its own, `put` shows a value: in the Academy it appears in the **Output** below the playground.

<code>
put "Hello, world!"
</code>

Press **Try it** above. The code goes into the playground on the right, runs, and its output appears below it. You can change it there and press **Run** (or Ctrl+Enter) as often as you like: nothing you type can break anything.

## Text and numbers

Text goes inside double quotes, so xTalk knows where it starts and ends. Programmers call a piece of text a **string**. Numbers need no quotes.

<code>
put "I am learning xTalk"
put 42
put 3.5
</code>

<tip>
Every `put` in the Academy gets a line of its own in the Output, so you can see each step of your program. In the IDE's Message Box, each `put` replaces the last one instead.
</tip>

<quiz>
Which line shows the words Good morning?
- put Good morning
* put "Good morning"
- "Good morning" put
= Text needs double quotes around it, and the command comes first: put, then what to put.
</quiz>

</starter>
<solution>

put 2026
</solution>

</hint>

lesson: Doing sums
id: sums
minutes: 6

Computers are very good at arithmetic. xTalk uses the symbols you know from maths, with `*` for times and `/` for divide:

<code>
put 7 + 5
put 7 - 5
put 7 * 5
put 7 / 5
</code>

## More operators

`^` raises to a power. `div` divides and drops what is left over; `mod` gives only what is left over. These two are more useful than they look: `mod` tells you whether a number is even, and turns seconds into minutes and seconds.

<code>
put 2 ^ 10
put 17 div 5
put 17 mod 5
</code>

## Which goes first

Just as in maths, `*` and `/` happen before `+` and `-`. Brackets change the order.

<code>
put 2 + 3 * 4
put (2 + 3) * 4
</code>

<quiz>
What does `put 20 mod 6` show?
- 3
* 2
- 3.33
= 6 goes into 20 three times (18), and 2 is left over. mod gives what is left over.
</quiz>

<challenge>
How many seconds are there in one day? Write one `put` that works it out from 24 hours, 60 minutes and 60 seconds, so the Output shows the answer.
<starter>
put 24
</starter>
<solution>
put 24 * 60 * 60
</solution>
<check>
line 1 of output is 86400 | the Output shows the seconds in a day
code contains "*" | it multiplies, and does not just type the answer
</check>
<hint>
Multiply the hours in a day by the minutes in an hour, and by the seconds in a minute.
</hint>
</challenge>

lesson: Joining words
id: joining
minutes: 6

Joining strings together is called **concatenation**. xTalk has two operators for it: `&` joins two values exactly, and `&&` joins them with a space between.

<code>
put "sun" & "flower"
put "sun" && "flower"
put "The answer is" && 6 * 7
</code>

## Special characters

Some characters are hard to type inside a string. xTalk gives them names: `quote` is a double quote, `return` starts a new line, `tab` and `space` are what they say.

<code>
put "She said" && quote & "hello" & quote
put "Line one" & return & "Line two"
</code>

## How long is it?

`the number of chars of` counts the characters in a string, spaces included. `length()` does the same.

<code>
put the number of chars of "xTalk"
put length("Hello world")
</code>

<quiz>
What does `put "Hot" & "dog"` show?
- Hot dog
* Hotdog
- "Hot" & "dog"
= & joins two strings exactly, with nothing between them. && would add a space.
</quiz>

<challenge>

<starter>
put "xTalk" & "is" & "fun"
</starter>
<solution>
put "xTalk" && "is" && "fun"
</solution>
<check>
line 1 of output is "xTalk is fun" | the Output says xTalk is fun
code contains "&&" | it joins with &&
</check>
<hint>
`&` sticks words together with no space. Which operator adds a space?
</hint>
</challenge>

lesson: Reading code
id: comments
minutes: 4

Programs are read by people far more often than they are written. Good programmers leave notes for the next reader, who is often themselves a month later.

A **comment** is a note that xTalk ignores. It starts with `--` (or `#`) and runs to the end of the line. A longer note can go between `/*` and `*/`.

<code>
-- Work out the area of a rectangle
put 8 * 5 -- width times height
/* Comments can also
   cover several lines */
</code>

## Read it like a sentence

xTalk was designed in 1987 for HyperCard, so that people who were not programmers could read a script aloud and understand it. Try it with this line:

<code>
put the number of words of "the quick brown fox" into tCount
put tCount
</code>

"Put the number of words of the quick brown fox into tCount" is nearly English. When you are stuck, reading your code aloud is a real debugging trick.

<note>
xTalk does not care about capital letters in its own words: `PUT`, `Put` and `put` are the same. Most people write them in lower case.
</note>

<quiz>
What does xTalk do with the line `-- add the bonus`?
- It adds the bonus
* It ignores it: it is a comment
- It stops with an error
= A line starting with -- is a comment: a note for people, which xTalk skips.
</quiz>

unit: Variables and values
icon: variable

Give values names, change them, and use xTalk's built-in functions.

lesson: Variables
id: variables
minutes: 7

A **variable** is a named box that holds a value. You put a value into it, and then use its name wherever you want the value.

<code>
put "Ada" into tName
put 36 into tAge
put tName && "is" && tAge
</code>

`put ... into` stores the value instead of showing it. From then on, `tName` stands for "Ada".

## Choosing names

A name starts with a letter and has no spaces. Many xTalk programmers start variable names with a small `t` (for "temporary"), which makes them easy to spot and avoids clashing with words xTalk already uses. That is a convention, not a rule.

<caution>
Do not name a variable after one of xTalk's own words, like `sum`, `length` or `the`. Use names like `tSum` and `tLength` instead.
</caution>

## A variable can change

Putting a new value into a variable replaces the old one. The right-hand side is worked out first, so a variable can even be used to change itself.

<code>
put 10 into tScore
put tScore + 5 into tScore
put tScore
</code>

<quiz>
After these lines, what is in `tColour`? `put "red" into tColour` then `put "blue" into tColour`
- red
* blue
- redblue
= put into replaces whatever was in the variable before.
</quiz>

lesson: Changing values
id: changing
minutes: 6

xTalk has commands that change a number in a variable directly: `add`, `subtract`, `multiply` and `divide`.

<code>
put 100 into tMoney
add 20 to tMoney
subtract 5 from tMoney
multiply tMoney by 2
put tMoney
</code>

## Before and after

`put ... after` adds to the end of what a variable holds, and `put ... before` adds to the front. This is how you build up a string a bit at a time.

<code>
put "middle" into tWord
put "start-" before tWord
put "-end" after tWord
put tWord
</code>

<tip>
`add 1 to tCount` is the xTalk way of counting. You will see it in nearly every program that loops.
</tip>

<quiz>
What is in `tTotal` after `put 3 into tTotal`, `add 4 to tTotal`, `multiply tTotal by 10`?
- 43
* 70
- 34
= 3 plus 4 is 7, and 7 times 10 is 70.
</quiz>

lesson: Functions that help
id: builtins
minutes: 7

A **function** takes some values, does something with them and gives back an answer. xTalk has hundreds built in. You call one by writing its name with the values in brackets:

<code>
put round(3.7)
put max(4, 19, 7)
put min(4, 19, 7)
put sqrt(81)
put abs(-12)
</code>

## Random numbers

`random(n)` gives a whole number from 1 to n, different each time. Games are made of it. Run this a few times:

<code>
put "You rolled a" && random(6)
</code>

## Using an answer

A function's answer can go anywhere a value can: into a variable, into a sum, or into another function.

<code>
put round(22 / 7, 2) into tPi
put "Pi is about" && tPi
</code>

<note>
`round(22 / 7, 2)` rounds to two decimal places. Many functions take extra values like this: the Dictionary (Help menu) lists each one.
</note>

<quiz>
What does `put max(3, round(8.6), 5)` show?
- 8.6
* 9
- 5
= round(8.6) is 9, and the biggest of 3, 9 and 5 is 9.
</quiz>

<challenge>
A square room has an area of 144. Use the function `sqrt` to put the length of one side.
<starter>
put 144
</starter>
<solution>
put sqrt(144)
</solution>
<check>
line 1 of output is 12 | the Output shows 12
code contains "sqrt" | it uses sqrt
</check>
</challenge>

lesson: Everything is text
id: types
minutes: 6

In many languages you must say whether a variable holds a number or a string. In xTalk, every value is text, and xTalk treats it as a number when you do arithmetic with it. That is why `"12" + 1` works.

<code>
put "12" + 1
put 5 & 5
</code>

## Asking what a value is

Because anything can be in a variable, you sometimes need to check. `is a number` and `is an integer` answer `true` or `false`.

<code>
put "42" is a number
put "forty-two" is a number
put 3.5 is an integer
</code>

## True and false

`true` and `false` are **booleans**: the answers to yes-or-no questions. You will use them with `if` in the next unit.

<code>
put 10 > 3
put "cat" is "dog"
put not (2 + 2 is 5)
</code>

<caution>
Doing arithmetic with text that is not a number stops your program with an error. Try it: the Academy explains what went wrong.
</caution>

<code error>
put "ten" + 1
</code>

<quiz>
What does `put 2 & 3 + 1` show?
- 6
* 24
- 33
= + happens before &, so 3 + 1 is 4, and & joins 2 and 4 into 24.
</quiz>

unit: Making decisions
icon: git-branch

Teach your programs to choose with if, else and switch.

lesson: If and else
id: if
minutes: 7

Programs become interesting when they make choices. `if` runs a statement only when a condition is true:

<code>
put 15 into tTemperature
if tTemperature > 25 then
   put "Wear a T-shirt"
else
   put "Bring a jumper"
end if
</code>

Change 15 to 30 in the playground and run it again. The structure is always the same: `if`, a condition, `then`, the lines to run, an optional `else` with the lines for "otherwise", and `end if`.

## On one line

A short `if` can go on one line, with no `end if`:

<code>
put 7 into tAge
if tAge < 13 then put "Child ticket"
</code>

## Comparing

`=` and `is` both mean "equal to". `<>` and `is not` mean "not equal". Then there are `<`, `>`, `<=` and `>=`.

<tip>
The lines inside an `if` are indented by three spaces. xTalk does not need it, but it makes the shape of the program easy to see. The playground indents for you after `then`.
</tip>

<quiz>
What does this show? `put 5 into x` then `if x >= 5 then put "yes" else put "no"`
* yes
- no
- nothing
= 5 is greater than or equal to 5, so the condition is true.
</quiz>

<challenge>
A test has a pass mark of 50. Put a score into `tScore`, then put `Pass` if it is 50 or more, and `Try again` if it is less. Try it with a few different scores.
<starter>
put 64 into tScore
</starter>
<solution>
put 64 into tScore
if tScore >= 50 then
   put "Pass"

   put "Try again"

</solution>
<check>

output is "Pass" or output is "Try again" | it puts Pass or Try again
(output is "Pass") is (word 2 of line 1 of code >= 50) | the answer is right for the score
</check>
<hint>
Use `>=` to test for "50 or more". Keep your first line as it is: the checks read the score from it.
</hint>
</challenge>

lesson: And, or, not
id: logic
minutes: 7

Real decisions often depend on more than one thing. `and` is true only when both sides are true; `or` is true when at least one is; `not` flips true and false.

<code>
put 14 into tAge
put true into tWithAdult
if tAge >= 12 and tAge <= 17 then put "Teenager"
if tAge >= 18 or tWithAdult then put "Can see the film"
if not tWithAdult then put "On your own"
</code>

## Questions about text

xTalk has operators that read naturally: `contains` looks inside a string, `begins with` and `ends with` check its edges, and `is among the items of` checks a list.

<code>
put "banana bread" into tFood
put tFood contains "nan"
put tFood begins with "ban"
put "pear" is among the items of "apple,pear,plum"
</code>

<quiz>
When is `tA or tB` false?
- When either one is false
* Only when both are false
- Never
= or needs just one true side, so it is only false when both sides are false.
</quiz>

<challenge>
A year is a **leap year** if it divides by 4, except years that divide by 100, which are only leap years if they also divide by 400. Write a function `isLeap(pYear)` that returns true or false. (You will learn about functions properly soon: fill in the condition.)
<starter>
function isLeap pYear
   return pYear mod 4 is 0
end isLeap

put isLeap(2024)
put isLeap(1900)
</starter>
<solution>
function isLeap pYear
   return (pYear mod 4 is 0 and pYear mod 100 is not 0) or pYear mod 400 is 0
end isLeap

put isLeap(2024)
put isLeap(1900)
</solution>
<check>
isLeap(2024) | 2024 is a leap year
not isLeap(2023) | 2023 is not
not isLeap(1900) | 1900 is not (it divides by 100)
isLeap(2000) | 2000 is (it divides by 400)
</check>
<hint>
`pYear mod 4 is 0` means "divides by 4". Combine three such tests with `and`, `or` and brackets.
</hint>
</challenge>

lesson: Many choices
id: switch
minutes: 7

When there are more than two choices, `else if` lets you test one condition after another. The first one that is true wins.

<code>
put 72 into tScore
if tScore >= 90 then
   put "A"
else if tScore >= 70 then
   put "B"
else if tScore >= 50 then
   put "C"
else
   put "D"
end if
</code>

## switch

When you compare one value with a list of possibilities, `switch` is tidier. Each `case` is a possible value; `break` ends that case, and `default` catches everything else.

<code>
put "Tuesday" into tDay
switch tDay
   case "Saturday"
   case "Sunday"
      put "Weekend!"
      break
   case "Friday"
      put "Nearly there"
      break
   default
      put "A school day"
end switch
</code>

<caution>
Forget a `break` and xTalk carries on into the next case. That is how "Saturday" and "Sunday" share their lines above, but it is also a classic bug.
</caution>

<quiz>
In the grade example, which grade does a score of 90 get?
* A
- B
- Both A and B
= The conditions are tested in order and the first true one wins: 90 >= 90, so A.
</quiz>

<challenge>
Write a function `sizeOf(pNumber)` that returns `small` for numbers under 10, `medium` for 10 to 99, and `large` for 100 or more.
<starter>
function sizeOf pNumber
   return "small"
end sizeOf

put sizeOf(5)
put sizeOf(50)
put sizeOf(500)
</starter>
<solution>
function sizeOf pNumber
   if pNumber < 10 then
      return "small"
   else if pNumber < 100 then
      return "medium"
   else
      return "large"
   end if
end sizeOf

put sizeOf(5)
put sizeOf(50)
put sizeOf(500)
</solution>
<check>

sizeOf(10) is "medium" | 10 is medium
sizeOf(99) is "medium" | 99 is medium
sizeOf(100) is "large" | 100 is large
</check>
</challenge>

unit: Repeating
icon: repeat

Make the computer do the boring part, over and over.

lesson: Counting loops
id: loops
minutes: 8

A **loop** runs the same lines again and again. The simplest says how many times:

<code>
repeat 3 times
   put "Hip hip hooray!"
end repeat
</code>

## Counting with a variable

`repeat with` counts for you, putting each number into a variable in turn. This is the loop you will use most.

<code>
repeat with tNumber = 1 to 5
   put tNumber && "squared is" && tNumber * tNumber
end repeat
</code>

It can count backwards with `down to`, and in bigger steps with `step`:

<code>
repeat with tCount = 10 down to 0 step 2
   put tCount
end repeat
put "Lift off!"
</code>

<tip>
Loops and `add` together are a pattern every programmer knows: start a total at 0, and add to it each time round.
</tip>

<code>
put 0 into tTotal
repeat with tNumber = 1 to 100
   add tNumber to tTotal
end repeat
put "1 + 2 + ... + 100 =" && tTotal
</code>

<quiz>
How many lines does `repeat with i = 2 to 6` followed by `put i` and `end repeat` show?
- 4
* 5
- 6
= It puts 2, 3, 4, 5 and 6: five numbers.
</quiz>

<challenge>
Put the 7 times table, from `1 x 7 = 7` to `10 x 7 = 70`, one line each.
<starter>
repeat with tNumber = 1 to 3
   put tNumber
end repeat
</starter>
<solution>
repeat with tNumber = 1 to 10
   put tNumber && "x 7 =" && tNumber * 7
end repeat
</solution>
<check>
the number of lines of output is 10 | ten lines
line 1 of output is "1 x 7 = 7" | the first line is 1 x 7 = 7
line 10 of output is "10 x 7 = 70" | the last line is 10 x 7 = 70
code contains "repeat" | it uses a loop
</check>
<hint>
Count from 1 to 10, and join the parts with `&&`: the number, "x 7 =", and the number times 7.
</hint>
</challenge>

lesson: Loops that decide
id: while
minutes: 7

Sometimes you do not know how many times to repeat: you want to keep going **while** something is true, or **until** it becomes true.

<code>
put 1 into tPaper
put 0 into tFolds
repeat while tPaper < 1000
   multiply tPaper by 2
   add 1 to tFolds
end repeat
put "Folded" && tFolds && "times, the paper is" && tPaper && "layers thick"
</code>

`repeat until` is the same idea the other way round:

<code>
put 0 into tRolls
repeat until random(6) is 6
   add 1 to tRolls
end repeat
put "It took" && tRolls && "rolls before a six"
</code>

## Loops that never stop

If the condition never changes, the loop runs for ever. This is called an **infinite loop**, and every programmer writes one sooner or later. The Academy stops any loop that is still going after ten seconds, and says so.

<caution>
In a loop that waits for a condition, make sure something inside the loop changes it. A `repeat while tCount < 10` with no `add 1 to tCount` never ends.
</caution>

<quiz>
How many times does this loop run? `put 1 into x`, `repeat while x < 20`, `multiply x by 3`, `end repeat`
- 2
* 3
- 20
= x goes 1, 3, 9, 27: the test fails once x is 27, after three times round.
</quiz>

<challenge>
Starting from 1, keep doubling a number until it is bigger than 500, then put the number.
<starter>
put 1 into tNumber
put tNumber
</starter>
<solution>
put 1 into tNumber
repeat until tNumber > 500
   multiply tNumber by 2
end repeat
put tNumber
</solution>
<check>
line 1 of output is 512 | the Output shows 512
code contains "repeat" | it uses a loop
</check>
</challenge>

lesson: For each
id: foreach
minutes: 7

Most loops go through a collection: every character of a word, every word of a sentence, every line of a list. `repeat for each` does exactly that, and it is fast.

<code>
repeat for each word tWord in "the cat sat on the mat"
   put toUpper(tWord)
end repeat
</code>

It works with `char`, `word`, `item` and `line`:

<code>
put 0 into tCount
repeat for each char tChar in "mississippi"
   if tChar is "s" then add 1 to tCount
end repeat
put "There are" && tCount && "s's in mississippi"
</code>

## Stopping early and skipping

`exit repeat` leaves a loop straight away; `next repeat` skips to the next time round.

<code>
repeat for each item tFruit in "apple,banana,stop,cherry"
   if tFruit is "stop" then exit repeat
   if tFruit is "banana" then next repeat
   put tFruit
end repeat
</code>

<quiz>
What does the last example put?
* only apple
- apple and cherry
- apple, banana and cherry
= banana is skipped by next repeat, and the loop ends at stop, before cherry.
</quiz>

<challenge>
Write a function `vowels(pText)` that returns how many vowels (a, e, i, o, u) are in pText.
<starter>
function vowels pText
   return 0
end vowels

put vowels("programming")
</starter>
<solution>
function vowels pText
   local tCount
   put 0 into tCount
   repeat for each char tChar in pText
      if tChar is among the chars of "aeiou" then add 1 to tCount
   end repeat
   return tCount
end vowels

put vowels("programming")
</solution>
<check>
vowels("programming") is 3 | programming has 3 vowels
vowels("xyz") is 0 | xyz has none
vowels("AUDIO") is 4 | AUDIO has 4 (xTalk compares letters without minding case)
</check>
<hint>
Loop with `repeat for each char`, and test each one with `is among the chars of "aeiou"`.
</hint>
</challenge>

unit: Text and lists
icon: type

Chunk expressions: xTalk's superpower for words, lines and lists.

lesson: Chunks
id: chunks
minutes: 8

Most languages make you count positions to get at part of a string. xTalk lets you ask for it by name: a **chunk**.

<code>
put "The quick brown fox" into tText
put word 2 of tText
put char 1 to 3 of tText
put the last word of tText
put the number of words of tText
</code>

The chunks are `char`, `word`, `item` (separated by commas) and `line`. You can ask for one, a range (`word 2 to 3`), or count from the end with negatives (`word -1`).

<code>
put "red,green,blue" into tColours
put item 2 of tColours
put "first line" & return & "second line" into tLines
put line 2 of tLines
put char 1 of word 2 of "hello world"
</code>

<tip>
Chunks work inside chunks, and the smaller one comes first: `char 1 of word 2`, never `word 2 of char 1`.
</tip>

<quiz>
What does `put item -1 of "cats,dogs,mice"` show?
- cats
* mice
- 3
= -1 counts from the end: the last item.
</quiz>

<challenge>
Write a function `initials(pName)` that returns the first letter of each word, in capitals. `initials("ada lovelace")` should give `AL`.
<starter>
function initials pName
   return char 1 of pName
end initials

put initials("ada lovelace")
</starter>
<solution>
function initials pName
   local tResult
   repeat for each word tWord in pName
      put toUpper(char 1 of tWord) after tResult
   end repeat
   return tResult
end initials

lesson: Where values live
id: scope
minutes: 7

A variable used inside a handler belongs to that handler alone: it is **local**. It is made fresh each time the handler runs and is gone when it ends. That is a good thing: handlers cannot trip over each other's variables.

<code>
command setIt
   put "inside" into tPlace
end setIt

put "outside" into tPlace
setIt
put tPlace
</code>

The `tPlace` in `setIt` is a different variable from the one outside, so the last line still puts "outside".

## Sharing a value

When handlers do need to share, a **script local** variable is declared at the top, outside any handler, with `local`. Every handler in the script can use it, and it keeps its value between calls.

<code>
local sCount

command tally
   add 1 to sCount
end tally

tally
tally
tally
put "Called" && sCount && "times"
</code>

<note>
The `s` at the start of `sCount` is another convention: `s` for script local. A `global` variable is shared by every script in the whole program, and its name usually starts with `g`. Use them sparingly.
</note>

<quiz>
Why did the first example put "outside"?
- setIt never ran
* The tPlace in setIt is local to setIt
- put cannot change a variable twice
= Each handler has its own local variables, so setIt changed only its own tPlace.
</quiz>

lesson: Messages
id: messages
minutes: 6

xTalk is an **event-driven** language. When something happens (a click, a key press, a card opening) xTalk sends a **message** with a name like `mouseUp` or `openCard`. If a handler with that name is in the right script, it runs.

That is all a command handler is: a handler for a message. When you write `sayHello` in your code, xTalk sends the message "sayHello", finds your handler, and runs it.

## The message path

A message starts at the object it is about (a button that was clicked, say) and travels upwards: from the button to its card, to the stack, and on to xTalk itself. The first handler with the right name on the way handles it. This journey is called the **message path**.

<code>
command whereAmI
   put "This handler is in" && the name of me
end whereAmI

whereAmI
</code>

In the Academy, your handlers live in the script of the stage: a stack made for your code. That is why `me` is a stack here.

<tip>
A handler can let the message carry on along the path with `pass`. That is how one script can react to a message and still let the next one have it.
</tip>

<quiz>
A button with no script is clicked. Where can a mouseUp handler for it be?
- Nowhere: it needs its own script
* In its card's or its stack's script
- Only in the Message Box
= The message travels up the message path, so a handler in the card or stack catches it.
</quiz>

lesson: Searching
id: searching
minutes: 8

An **algorithm** is a recipe for solving a problem, step by step. Some recipes are so useful that every programmer learns them. The first two: find the biggest thing in a list, and find where something is.

## The biggest

Keep the best so far. Look at each item; if it beats the best, it becomes the best.

<code>
put "7,3,19,4,11" into tList
put item 1 of tList into tBiggest
repeat for each item tNumber in tList
   if tNumber > tBiggest then put tNumber into tBiggest
end repeat
put "The biggest is" && tBiggest
</code>

## Linear search

To find where something is, look at each item in turn until you find it. If you get to the end, it is not there.

<code>
function positionOf pWanted, pList
   local tIndex
   put 0 into tIndex
   repeat for each item tItem in pList
      add 1 to tIndex
      if tItem is pWanted then return tIndex
   end repeat
   return 0
end positionOf

put positionOf("cherry", "apple,banana,cherry,date")
put positionOf("kiwi", "apple,banana,cherry,date")
</code>

<note>
In a list of a million items, a linear search may look at a million items. If the list is sorted, a **binary search** looks at the middle, throws away the half that cannot hold the answer, and repeats: about twenty looks for a million items.
</note>

<quiz>

- 1
- 25
* 50
= It has to check every item before it can be sure the thing is not there.
</quiz>

lesson: Sorting

xTalk's `sort` command sorts for you, but sorting by hand is how programmers learn to think about algorithms. The simplest method is **bubble sort**: go through the list comparing each pair of neighbours, and swap them if they are the wrong way round. Repeat until a whole pass makes no swaps.

<code>
put "5,1,4,2,8" into tList
put true into tSwapped
repeat while tSwapped
   put false into tSwapped
   repeat with tIndex = 1 to the number of items of tList - 1
      if item tIndex of tList > item tIndex + 1 of tList then
         -- swap the two neighbours
         put item tIndex of tList into tTemp
         put item tIndex + 1 of tList into item tIndex of tList
         put tTemp into item tIndex + 1 of tList
         put true into tSwapped
      end if
   end repeat
   put tList
end repeat
</code>

Each line of the Output is one pass: watch the big numbers "bubble" to the end.

## Swapping

Swapping two values needs a third variable to hold one of them for a moment, just as swapping the drinks in two glasses needs a third glass.

<important>
Bubble sort is easy to understand but slow on big lists: sorting a thousand items can take nearly a million comparisons. Faster methods (merge sort, quicksort) split the list in halves. xTalk's own `sort` uses a fast one.
</important>

<quiz>
Why does the swap need `tTemp`?
- xTalk cannot put a value into an item
* Without it, the first value would be overwritten before it was copied
- It makes the sort faster
= The first put replaces item tIndex, so its old value must be saved somewhere first.
</quiz>

lesson: Recursion
id: recursion
minutes: 8

A function can call itself. This is called **recursion**, and it suits problems that contain smaller copies of themselves.

The factorial of a number (written 5! in maths) is it times every whole number below it: 5! = 5 x 4 x 3 x 2 x 1. But notice that 5! is just 5 x 4!, and 4! is 4 x 3!, and so on, down to 1! which is 1.

<code>
function factorial pNumber
   if pNumber <= 1 then return 1
   return pNumber * factorial(pNumber - 1)
end factorial

put factorial(5)
put factorial(10)
</code>

Every recursive function needs a **base case**: a simple case it answers without calling itself (here, 1). Without one, it would call itself for ever.

<caution>
If the base case is never reached, xTalk stops with an error once the calls are thousands deep. That is the recursive version of an infinite loop.
</caution>

<quiz>
What is `factorial(4)`?
- 10
* 24
- 16
= 4 x 3 x 2 x 1 is 24.
</quiz>

<challenge>
The Fibonacci numbers start 1, 1, and each one after is the sum of the two before: 1, 1, 2, 3, 5, 8, 13 ... Write a recursive function `fib(pN)` that returns the pN-th one, so fib(1) and fib(2) are 1, and fib(7) is 13.
<starter>
function fib pN
   return 1
end fib

put fib(7)
</starter>
<solution>
function fib pN
   if pN <= 2 then return 1
   return fib(pN - 1) + fib(pN - 2)
end fib

put fib(7)
</solution>
<check>
fib(1) is 1 and fib(2) is 1 | the first two are 1
fib(7) is 13 | the seventh is 13
fib(12) is 144 | the twelfth is 144
</check>
<hint>
The base case is pN of 1 or 2. Otherwise, return fib(pN - 1) + fib(pN - 2).
</hint>
</challenge>
