A property that works itself out

A custom property (Custom properties) holds whatever you put in it. A getprop handler goes further: when a script asks for the property, the handler runs, and what it returns is the property's value. The property can be worked out from others, so it is never out of date:

Only celsius is stored. fahrenheit is a virtual property: reading it runs the getprop handler, and setting it runs the setprop handler, which sets celsius instead. To the scripts that use it, it is a property like any other.

One handler for many objects

The examples in this lesson make their controls with create (Making controls from a script), so that each one runs in the playground in one piece. In a stack of your own you would drag the same controls from the Tools palette, name them in the Property Inspector, and put the handlers into their scripts: the code works the same either way.

getprop and setprop are messages, sent to the object whose property is used, so they travel the message path like any other. A handler further along it, in a card, a stack, a behavior or a library, can serve every object below it. the target is the object whose property it is:

The property inside its own handler

Inside its own handler, a property of me is just what is stored: reading it there does not run the getprop handler again, and setting it there stores the value without running the setprop handler again.
