A table is lines and items

The xTalk way to keep a table is text: a line for each row, and the row's values as items, separated by tabs. Tabs, because values often contain commas but almost never tabs. Every chunk expression then works on the table: line 3 is the third row, and item 2 of line 3, with the itemDelimiter set to tab, one value.

CSV: comma-separated values

Spreadsheets and databases swap tables as CSV. It looks simple, a comma between values, but a value can itself hold a comma, a quote or even a line break. Then the value is put in double quotes, and a quote inside it is doubled:

Name,Note
Ada,"Lovelace, Countess"
Grace,"She said ""hi"""

So splitting at every comma breaks such a file. Reading CSV properly means going through it a character at a time, remembering whether you are inside quotes. This function turns CSV into the xTalk table, tab-separated:

A line break inside quotes is kept in the value too, since only a return outside quotes ends a row. (A tab inside a value would split it in the table; replace tabs in values first if your data may have them.)

CSV files from Windows end their lines with a carriage return and a line feed. Read them with URL "file:", which turns those into xTalk's return, or replace numToChar(13) with empty after reading with binfile:.

Showing a table in a field

A field shows tab-separated text as columns when you set its tabStops, the positions of the columns from its left edge. vGrid and hGrid draw lines between columns and rows, and a line can have its own style and colour, which makes a header row:

The field's text is still the plain table, so everything in this lesson works on it directly. For tables the user edits cell by cell, with sorting by a click on a column, the IDE's Tools palette has the Data Grid, built on the same ideas.
