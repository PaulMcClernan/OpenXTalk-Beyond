Signing in without a password: OAuth2

A program that reads someone's files on Dropbox, or posts to their team's Slack, needs their permission, but should never see their password. OAuth2 is how almost every web service handles this. Your program opens the service's own sign-in page; the person signs in there and agrees to what your program asks for, its scopes; and the service gives your program an access token, a long random string that stands for that permission and nothing more. The person can take it back at any time from the service's settings.

First you register your program with the service, on its developer pages. It gives you a client id and a client secret, and the addresses of its sign-in page and its token page. You also give it a redirect address, where the sign-in page sends the person when they are done: for a desktop program it is http://127.0.0.1: and a port, because the OAuth2 library listens there itself. OAuth2 shows the sign-in page in a window of its own and waits. When the person is done, it is an array of what the token page sent: access_token, and often refresh_token and expires_in, the seconds the access token lasts. If they close the window or say no, the result says so. The port, 54303 here, must match the redirect address you registered; one from 49152 to 65535 is unlikely to be in use.

Anyone who has your client secret can pretend to be your program. Do not put it in a stack you give away unprotected: put it in a script of a password-protected stack, or ask each person to register the program themselves and type in their own id and secret. And keep tokens as you would passwords: anyone holding one has the permission it stands for.

When the token runs out

An access token usually lasts hours, not months. When the service starts answering 401, the refresh token gets a new one without asking the person again: OAuth2Refresh takes the token page, your id and secret, the refresh token and the port, and puts a new array in it:

Dropbox

The Dropbox library wraps Dropbox's whole API, a command for each thing it can do: dropboxListFolder, dropboxUpload, dropboxDownload, dropboxCreateFolder, dropboxMove, dropboxDelete, sharing links and more. Dropbox paths start with a slash, and the top of the person's Dropbox is the empty path. Register your program in the Dropbox App Console to get its id and secret; its pages also say what each call sends back.

Messages from a service: checking the signature

Many services can also call you: when something happens, they send a webhook, a request to a server of yours. Anyone could send such a request, so the service signs each one with an HMAC of its content and a secret you both know (Hashing and security), in a header. The second request carries a real signature, copied from the first, but for a different message, so it is refused. The Content-Type matters too: post sends form data unless told otherwise, and the server library takes form data apart into parameters and leaves content empty, so the signature would be worked out over nothing. Each service says how it signs (which hash, which header, whether a time is mixed in to stop an old message being sent again), so follow its documentation exactly.

Try it yourself

A token array from OAuth2 has expires_in, the seconds it lasts from when it was given. Write a command keepToken that stores the array with the moment it arrived, and a function tokenIsFresh that takes that moment and is true while there is more than a minute left, so a program can refresh before a request fails rather than after.
