A file is a container

The simplest way to use a file in xTalk is to treat it as a container, like a variable or a field. URL "file:" followed by the file's path reads the whole file, and putting into it writes the whole file:

Use after to add to the end of a file without reading it first, which is handy for a log:

file: or binfile:

file: reads and writes text, and changes line endings to suit the system. binfile: reads and writes the bytes exactly as they are: use it for pictures, sound and any data that is not plain text, and for text whose encoding you choose yourself:

For text in any language, the safe pair is textEncode(tText, "UTF-8") into a binfile: URL to write (Unicode and text encodings), and textDecode(URL ("binfile:" & tPath), "UTF-8") to read, so the encoding is always UTF-8, whatever system the stack runs on.

Where to keep files

A program should not scatter files anywhere. specialFolderPath gives the right folder on every system:

  • specialFolderPath("documents"): the user's documents, for files they made and will look for;
  • specialFolderPath("support"): the place for a program's own settings and data (add a folder with your program's name);
  • specialFolderPath("temporary"): for files you need only for a moment, as in these examples;
  • specialFolderPath("home") and specialFolderPath("desktop").

Paths in xTalk always use / between folders, on Windows too, so the same script works everywhere. With the itemDelimiter set to /, a path's items are its folders:

Folders and listing files

files(folder) lists the files in a folder, a line each, and folders(folder) its folders. create folder, rename file and delete file and delete folder do what they say:

delete file does not use the Trash or Recycle Bin: the file is gone. Check the path twice before deleting in a loop.
