A web page in a card

The Browser widget is a whole web browser in a rectangle of the card: it shows pages from the internet, runs their JavaScript, follows their links and plays their videos. Build a card with one:

  1. Make a new stack, or go to an empty card. In Edit mode, drag a classic Field to the top of the card, stretch it from edge to edge, make it one line high, and name it Address.
  2. Drag a Browser from the widgets of the Tools palette below it, make it fill the rest of the card, and name it Web.

What happens in the page

The page loads on its own, while your scripts go on, and the widget sends messages as it does: browserNavigateBegin when it starts to go to a new address, whether a script set it or someone clicked a link; browserDocumentLoadComplete when the page is there; and browserDocumentLoadFailed, with the reason, when it could not be loaded. Native buttons and fields

A classic button looks much the same on every system. A native widget is the system's own control, drawn and worked by the system, so it looks and behaves exactly as the rest of the system does. There are native buttons for the Mac, iOS, Android and HTML5, and native one-line fields for the Mac and Android. Each is the real thing only on its own system; anywhere else it is a grey stand-in with the system's logo and its label, or a field's name, so a card for the Mac can be laid out on any computer:

A native button sends mouseUp when it is clicked, as any button does, and its label is its text. A native field's text is its text, and the Mac's sends returnKey when Return is pressed in it. On a phone a native field brings up the system's own keyboard, and the Android one has properties for which keyboard, such as keyboardType.
