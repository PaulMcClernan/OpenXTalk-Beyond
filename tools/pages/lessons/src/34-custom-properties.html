Properties of your own

Besides the properties xTalk gives every object, an object can hold custom properties: any name you choose, any value you like. You set and read them exactly like built-in ones. The usual habit is to start their names with c (or u, for "user"), so they never clash with a property xTalk may add one day.

  1. On a new card, drag a Standard Button and name it Lamp.
create button "Lamp"
set the rect of it to 40,40,122,63

A custom property nobody has set is simply empty. Select the button and open the Property Inspector's Custom Properties section: cIsOn and cWatts are listed there with their values, and you can add, change and delete custom properties by hand too.

Why not a variable?

A variable lasts no longer than the program runs (Where variables live). A custom property belongs to its object, so it is saved with the stack: close the stack, open it next week, and the value is still there. That makes custom properties the natural place for:

  • settings and preferences: the cSoundOn of this stack
  • the state of an object: how many times a button was clicked, which page a book was left open at
  • data an object carries: the price of a product card, the answer to a quiz question
  1. On a new card, drag a Standard Button, make it about 200 points wide and 50 high, and name it Counter.
create button "Counter"
set the rect of it to 140,150,340,200

The first click finds cClicks empty, which counts as 0 in a sum. The count lives in the button, not in a variable of the script: save the stack (File > Save), close it, open it again, and the next click says 5.

Listing them

the customKeys of an object lists the names of its custom properties, and the customProperties gives them all as an array. Setting the customProperties to an array replaces them all at once:

  1. On a new card, drag a Standard Button and name it Product.
create button "Product"
set the rect of it to 40,40,122,63

After the click, put the cPrice of button "Product" in the Message Box says 24.5.

Properties with keys

A custom property can be read and set a key at a time, which groups related values under one name. The group is called a custom property set: the customProperties with its name gives the whole set as an array, and the customKeys with its name lists its keys.

  1. On a new card, drag a Standard Button and name it Book.
create button "Book"
set the rect of it to 40,40,122,63

Switching sets

An object can have several sets, and its customPropertySet says which one plain the cName reads and writes. One use is translation: a set for each language, with the same names in each, and the stack switches between them.

  1. On a new card, drag a Standard Button and name it Greeting.
create button "Greeting"
set the rect of it to 40,40,122,63

The Inspector's Custom Properties section has a menu of the object's sets, to look at each one.

The other side of the coin

Because any unknown name makes a custom property, a misspelled built-in property quietly creates one instead of failing, as Properties showed. The c at the front of your own names helps here too: a property without it should be one of xTalk's.

And when a property should be worked out each time it is read, rather than stored, a getprop handler can answer for it: the lesson Virtual properties shows how.

Try it yourself

On a new card, drag three Standard Buttons for products, Pen, Notebook and Bag, and give each a cPrice in the Inspector's Custom Properties: 1.5, 4 and 25. Then add a fourth button, Total, whose script goes through the buttons and puts the total price.

  1. Drag three Standard Buttons in a row and name them Pen, Notebook and Bag.
  2. For each, in the Property Inspector's Custom Properties, add a property cPrice: 1.5 for the pen, 4 for the notebook and 25 for the bag.
  3. Drag a fourth Standard Button under them and name it Total.
repeat for each item tProduct in "Pen,Notebook,Bag"
   add 1 to tCount
   create button tProduct
   set the rect of it to tCount * 100 - 60, 40, tCount * 100 + 22, 63
   set the cPrice of it to item tCount of "1.5,4,25"
end repeat
create button "Total"
set the rect of it to 40,80,122,103
Show a solution

The button Total has no cPrice, and an empty value adds nothing.
