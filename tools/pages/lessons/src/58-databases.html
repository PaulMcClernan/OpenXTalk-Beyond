When a file is not enough

A text file or a JSON file holds a few hundred records well. Thousands of records that you search, sort, update one at a time and must never lose belong in a database. SQLite keeps a whole database in one file, needs no server, and comes with OXT-Beyond; you talk to it in SQL, the language every relational database understands.

The database commands begin with rev, and come from an external the IDE loads as it starts, so a standalone that uses them needs Database and the SQLite driver ticked in its settings (Shipping your program).

Opening a database and making a table

revOpenDatabase("sqlite", path) opens the file, making it if it is not there, and returns a connection number to use with every other command; anything that is not a number is an error. revExecuteSQL runs SQL that changes something, and leaves the number of rows changed, or an error, in the result:

For a database that lasts only while the program runs (a cache, a quick sort of a big list), open ":memory:" instead of a path, as the rest of this lesson does.

Inserting safely: placeholders

Never build SQL by joining in values: a name such as O'Brien breaks it, and a value typed by a stranger can turn into SQL of their own, which is called SQL injection. Write :1, :2 and so on where the values go, and give the names of the variables that hold them after the SQL. The values then never become part of the SQL, whatever they contain:

Asking questions: revDataFromQuery

revDataFromQuery runs a SELECT and returns the answer as text: the columns separated by the first delimiter, the rows by the second. With a tab and a return, that is the xTalk table of Tables and CSV, ready for a table field. Placeholders work here too:

Record by record: cursors

For a big answer, or when you want each column by its name, revQueryDatabase returns a cursor: a place in the answer that you move through a record at a time. revDatabaseColumnNamed reads a column of the current record, revMoveToNextRecord moves on, and revQueryIsAtEnd says when there are no more. Errors

SQL with a mistake in it does not stop the script: revExecuteSQL leaves the database's words in the result, and revDataFromQuery returns them, starting with revdberr. Check both:

Many changes at once: transactions

A transaction groups changes so that they all happen, or none do: a transfer takes from one account and adds to another, never just one of the two. Begin one with BEGIN, and end it with COMMIT to keep the changes or ROLLBACK to undo them. It is also much faster for many inserts, because the file is written once instead of once a row:
