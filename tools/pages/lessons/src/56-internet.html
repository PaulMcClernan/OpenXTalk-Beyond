A web server for the examples

So that this lesson's examples run anywhere, even with no internet, each one starts a tiny web server on your own computer first, with the HTTP server library that comes with OXT-Beyond: httpdStart names the handler that answers each request and a port (0 lets the system choose a free one, which it puts in it), and the handler answers with httpdResponse. The address is then http://127.0.0.1: and the port: 127.0.0.1 always means this computer.

Everything on the client side works the same with any address on the internet, such as https://example.com/. And the server side is useful too: a program can serve a page to a phone on the same network, or answer another program.

Fetching: URL

URL with an http: or https: address is a container, like URL "file:" (Reading and writing files): reading it fetches the page. The script waits until it arrives, and the result says what went wrong, if anything:

Check the result after every fetch. A server that answers with an error still sends a page (here, No such page), and a server that cannot be reached sends nothing, so the page alone does not tell you whether it worked.

Asking with parameters

A request can carry values in its address, after a ?: ?q=tea&page=2. A value with spaces, & or accents must be encoded first. Encode text as UTF-8 and then with urlEncode, which is what servers expect today:

Sending: post

post sends data to a server, as a form does, and puts the server's answer in it. Form data is name=value pairs joined with &, each value encoded. To send JSON, say so with a Content-Type header in the httpHeaders, the extra headers sent with each request:

Set the httpHeaders back to empty when you are done, or the headers go with every later request too. A web service that needs a key usually takes it in a header: Authorization: Bearer and the key.

What the server sent back

Loading in the background

Reading URL makes the script wait, and a slow server makes the program wait with it. load URL starts the download and returns at once; when it has finished, the message you name arrives with the address and its status, and the page is then in the cache, where URL reads it at once. unload URL frees the cache:

The status is cached when the download worked, and error, timeout or contacted when it did not get that far. URLStatus(address) gives the same while it is still going, with how much has arrived, for a progress bar.

Opening the user's browser

launch url opens an address in the user's own web browser, or a mailto: address in their email program. It does not fetch anything for the script:

Real services are on https:, which encrypts the connection and checks the server's certificate. Use https: addresses whenever a service offers them, and never send a password or a key over plain http:.

Try it yourself

Build a tiny web service and its client. The server answers /square?n= with JSON such as {"n": 12, "square": 144}, and a 400 error when n is not a number. The client asks for 12 and for twelve, reads the JSON, and puts the square or the problem.
