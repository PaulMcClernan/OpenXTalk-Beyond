Bytes, not characters

A picture, a sound, a zip file or a network message is binary data: a row of bytes, each a number from 0 to 255, that is not text and must not be treated as text. xTalk keeps such data as it is, and chunk expressions with byte work on it. byteToNum and numToByte go between a byte and its number:

Text becomes bytes through an encoding, and bytes become text again only through one (Unicode). Read a binary file with URL "binfile:", never URL "file:", which changes line endings and so changes the bytes (Reading and writing files).

Seeing bytes: hexadecimal

Bytes are easiest to read in hexadecimal, two digits a byte from 00 to ff. binaryDecode with the format H* turns data into hexadecimal, and binaryEncode with H* turns it back:

Packing numbers: binaryEncode and binaryDecode

Binary formats store numbers in a fixed number of bytes. binaryEncode packs values into bytes by a format, a letter for each value, and binaryDecode unpacks them with the same format. The letters you will use most:

LetterPacksBytes
Ca whole number from 0 to 2551
na whole number from 0 to 65,535, biggest byte first2
Na whole number up to about 4 billion, biggest byte first4
f, da number with decimals, in the computer's own order4, 8
acharacters, as many as the count after it (a3)the count
Hhexadecimal digits, two a byte (H*: all of them)half the digits

In the hexadecimal you can see each value: 01, then 513 as 0201 (2 × 256 + 1), then a million as 000f4240, then the codes of abc.
