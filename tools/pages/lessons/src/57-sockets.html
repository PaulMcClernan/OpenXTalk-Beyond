A line between two programs

A web request (The web and the internet) asks a question and gets one answer. A socket is a lasting two-way connection: both ends can write whenever they like, for as long as it stays open. Chat programs, multiplayer games and devices on a network all talk this way.

One program is the server: it listens on a port, a number from 1 to 65535 on its computer. The other is the client: it connects to the server's address and port. Once connected, the two are equal. In this lesson's examples one script plays both parts, on this computer (127.0.0.1), so they run anywhere.

The server: accept connections

accept connections on port starts listening. Each time a client connects, the message you name arrives with the new connection's id, which is the client's address and port, and is how you write to it, read from it and close it:

Closing the port stops the listening; connections already made stay open until they are closed too. Use a port above 1024 (lower ones need special permission), and one no other program on the computer uses.

The client: open socket

open socket to the address and port connects, and the message you name arrives once the connection is made. Nothing should be written before it does.

Writing and reading with messages

write ... to socket sends data. read from socket takes data that has arrived: until return for a line, or for a number of bytes. With with message, the read returns at once, and the message arrives with the data when it has all come, so the program never stops to wait for the other end. Follow the order of the lines: nothing happens during the script itself but setting things up. Everything after the first line happens in messages, as the data travels. That is the shape of every socket program: a handler for each thing that can arrive.

A read with until return gets the line with its return, as the examples show by taking line 1. A read gets one piece: to keep listening for the next line, read again in the handler, as the try-it below does.

When things go wrong

Networks fail: the server is not there, the other end goes away, nothing arrives. The engine reports each with a message to the object that opened the socket: socketError with the socket and what went wrong, socketClosed when the other end closes, and socketTimeout when a read has waited longer than the socketTimeoutInterval:

the openSockets lists the connections and ports still open, a line each: check it to make sure a program closes what it opens.

A protocol of your own

The two ends must agree how a message ends, or the reader cannot tell one from the next: this agreement is a protocol. The simplest is a line each, as above, which suits text that has no line breaks in it. For anything else (text with returns, pictures, files) send the length first, and read exactly that many bytes:

Over the internet, use open secure socket and accept secure connections, which encrypt everything with TLS as https: does. OXT-Beyond's own libraries go further for particular jobs: ENet (fast messages for games), WebRTC data channels (straight between two users) and Tor, each in the Dictionary.

Try it yourself

Write a calculator server: it reads lines such as add 2 3 or times 4 5, answers each with the result, and keeps reading. The client sends both questions, one after the other as each answer arrives, puts the answers, then closes.
