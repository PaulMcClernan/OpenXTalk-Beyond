A second language for extensions

Everything so far was xTalk script. OXT-Beyond has a second language, xTalk Builder (the language of .lcb files, known from LiveCode as LiveCode Builder), for writing extensions: libraries that add commands and functions, and widgets, new kinds of control that draw themselves. Most of the libraries and widgets in the Extensions folder are written in it, and it can call code written in C directly, which is how OXT-Beyond's own libsodium, ENet and Box2D extensions are made.

It reads much like xTalk, with three big differences:

  • It is compiled ahead of time into a module (a .lcm file) by lc-compile, which finds many mistakes before anything runs.
  • It is typed: every variable and parameter is declared with its type, such as String, Number, Integer, Boolean, List, Array or Data, and must be declared before it is used.
  • It has no chunks of objects on cards: a library works with values, and a widget draws on a canvas.

A widget

A widget is a control whose looks and behaviour you write. Its module begins with widget, and the engine sends it messages: OnCreate when one is made, OnPaint whenever it must be drawn, OnMouseUp when it is clicked, and others. Calling C directly

binds to "c:strlen" names the function; for a library of your own it is "c:mylibrary>my_function", and the compiled library goes in the extension's code folder, a folder for each platform, such as code/x86_64-linux and code/x86_64-win32.

C code runs without any of xTalk's safety: a wrong type or a bad pointer crashes the whole program. Keep foreign handlers few and simple, check every value before it crosses, and catch every C++ exception on the C side, as OXT-Beyond's own extensions do.

Building and sharing an extension

In the IDE, Tools > Extension Builder opens a .lcb file, compiles it, shows the errors on their lines, and with Test loads it and makes a test stack (for a widget, with one on it). Install adds it to the IDE for good, and Package makes a .lce file to give to others. A script can load a compiled module itself with load extension from file, which is how a standalone carries one, and the Standalone Application Settings include the extensions it uses.

The xTalk Builder reference is in the Dictionary, under the LCB entries, and the extensions in the IDE's Extensions folder, including OXT-Beyond's own, are good examples to read.

Try it yourself

Add a library with a public handler lessonReverseWords that takes a String and returns its words in reverse order. In xTalk Builder, split by a space into a List, go through it with repeat with from the end, and combine the result with spaces. Use it from script on one small step for a cat.
