Everyone shares

BitTorrent shares a file among many computers at once. Each one, a peer, fetches pieces from the others and gives its own pieces back, so no single server carries it all, and the more people want a file, the faster it spreads. The xTalk Suite's TorrentXT brings libtorrent, the engine inside many BitTorrent programs, to xTalk; its handlers begin with bt.

The examples stay on this computer: they share tiny files of their own, in a folder of their own, and turn off the ways a session finds peers on the internet.

The session

btStartSession starts the one session that runs everything; only one may run at a time, and a second call gives 0. btStopSession stops it, and you must always stop it when you are done: nothing does it for you. The examples keep the session in a global (Scope), so a run that stops halfway with an error is cleaned up by the next:

A session has hundreds of settings, each with a name. btSetBool turns one on or off, btSetInt sets a number and btSetString some text; each gives 0 when it works and -3 for a name it does not know, and btGetSetting reads one back. Making a torrent

A torrent describes what is shared: the names and sizes of the files, and a fingerprint of each piece, so every piece can be checked as it arrives. btCreateTorrent makes one from a file or a folder and gives its bytes, to save as a .torrent file and give to others. It needs no session. Its other parameters are the piece size (0 lets it choose), options (0 for the usual) and trackers, servers that introduce peers:

Seeding

To share a file, add its torrent to the session with btAddTorrentFile, saving into the folder that already holds the file. The session checks every piece, finds that it has them all, and starts seeding: giving pieces to whoever asks. btTorrentStatus gives an array about a torrent: its "state" (which btStateName says in words), its "progress" from 0 to 1, its "name", its "totalSize" and more:

The info hash names a torrent everywhere: two people with the same hash are sharing the same files.

Magnet links

A magnet link is a torrent in one line of text: its info hash and a name. Anyone with the link can fetch the rest from peers. btAddMagnet adds one, with the folder to save into. Here the state stays "fetching metadata", because with the DHT off and no trackers no peer can send the torrent; online, one would:

btPause stops a torrent and btResume starts it again; btSetTorrentLimits limits its speed, and the queue handlers (btQueueUp, btQueueTop and the rest) decide which goes first.

Events

The session works on threads of its own and keeps a queue of what happened: a torrent added, resumed, finished, paused, an error. btPoll gives every event since the last poll, oldest first, as an array, each with a "name" and the "torrent" it is about. The files in a torrent, and stopping

A torrent of a folder holds every file in it. btFileList lists them, each with its "path", "size", "progress" and "priority", and btSetFilePriority sets one, counting files from 0: 0 skips the file, 4 is usual and 7 comes first. (A path with .pad in it is a padding file, empty space that lines files up with pieces, and nothing is saved for it.) btRemoveTorrent takes a torrent out of the session, deleting its files with true and keeping them with false:

Share only what you have the right to share, and remember that peers see each other's addresses. An app should stop its session in closeStack, before it quits. Learn TorrentXT (Help > Examples) and the Dictionary have every handler.
