Values

Everything a program works with is a value: a name, a price, a line of a poem, the number of lives left in a game. In xTalk the two kinds you will use most are text and numbers.

Text goes between double quotes, so that xTalk knows exactly where it starts and ends. Programmers call a piece of text a string. Numbers are written as they are, with a point for the decimals and a minus sign for the negatives.

The last line is text that happens to be made of digits. It looks the same as the number 42, and in xTalk it mostly behaves the same too: Everything is text explains why.

Why the quotes matter

Without quotes, xTalk reads a word as a name: the name of a variable, or one of its own words. With quotes, it is just text. Compare these:

In quotes, 2 + 2 is three characters to show as they are. Without them it is a sum, which xTalk works out. And pi without quotes is one of xTalk's built-in constants, a name for a value it already knows.

xTalk shows pi rounded to six places. It knows many more: Formatting text shows how to choose how many decimals a number shows.

Capital letters

xTalk does not mind how you capitalise its own words: PUT, Put and put are the same command. Most people write them in lower case and keep capitals for the names they make up, like tTotalScore. What is inside quotes is shown exactly as you typed it.

Notes for people: comments

A comment is a note that xTalk ignores, for whoever reads the code next (very often yourself, a month later). It starts with -- or # and runs to the end of the line. A longer note can go between /* and */, over as many lines as you like.

A good comment says why, not what: the code already says what it does. "Times 1.2 for the VAT" helps the next reader; "multiply by 1.2" does not.

A line that goes on

A statement normally fits on one line. When one gets too long to read, end the line with a backslash \ and carry on below: xTalk reads the two lines as one.
