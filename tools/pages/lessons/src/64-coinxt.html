Coins are keys

Nobody holds a bitcoin the way you hold a coin. What you hold is a private key, 32 secret bytes, and whoever has the key can spend what it controls. CoinXT is the xTalk Suite's layer over trezor-crypto and libsecp256k1, the code that hardware wallets and Bitcoin itself run: it makes keys, addresses, recovery words and signatures for Bitcoin and Ethereum. Its handlers begin with cx.

The keys in this lesson are made from phrases and famous test values, so that every run gives the same answers to check. Anyone can make them again. They are for learning: never send real coins to them. A real key comes from secure random bytes, and lives in a wallet, not a script.

Hashes

Coins run on hashes (fingerprints), 32 bytes each. cxSha256 is the hash Bitcoin uses, cxHash256 runs it twice, which is how Bitcoin names blocks and transactions, and cxKeccak256 is Ethereum's. cxHexEncode spells bytes as hex:

Private and public keys

A private key is 32 bytes, almost any 32 bytes; cxSeckeyIsValid checks. From it, cxPublicKey makes the public key, which is safe to share and from which nobody can work back to the private one: 33 bytes in its short (compressed) form, 65 in its long form, which Ethereum uses:

Addresses

An address is where people send you coins, made from your public key. One Bitcoin key has several kinds, and the first letters say which: cxBtcAddressP2PKH gives the oldest kind, starting with 1; cxBtcAddressP2WPKH gives SegWit, starting with bc1q, cheaper to spend from; and cxBtcAddressP2TRFromInternal gives Taproot, starting with bc1p, from the 32-byte "x-only" key of cxXOnlyPubkey. Catching typos

A mistyped address sends coins nowhere, for ever, so each kind carries a checksum: letters worked out from the rest, which a typo makes disagree. Ethereum hides its checksum in the capital letters: cxEthAddressChecksum writes them, and cxEthAddressIsChecksummed checks them. cxWifEncode writes a private key as WIF text, which wallets import, and cxBase58CheckDecode stops with an error when a letter of such text is wrong:

A SegWit address checks its network as well: cxSegwitAddressDecode takes one apart for the network you name, "bc" for real Bitcoin or "tb" for the test network, and refuses the other, so a test wallet cannot send real coins by mistake:

Twelve words

A wallet is backed up as a recovery phrase: twelve or twenty-four ordinary words, written on paper, that rebuild it on any device. cxMnemonicFromEntropy turns 16 random bytes into 12 words from a list of 2048, and cxMnemonicValidate checks them: the last word holds a checksum, so a wrong word is caught. Sixteen zero bytes are a famous test value:

One phrase grows a whole tree of keys. cxMnemonicToSeed turns the words (and an optional passphrase) into a 64-byte seed, cxHdFromSeed makes the root of the tree, and cxHdDerivePath walks a path such as m/84'/0'/0'/0/0 to one key. Signing

To spend, you sign: you prove you hold the private key without showing it. A signature covers exactly 32 bytes, so you sign the hash of the message. cxSign signs, and cxVerify checks with the public key: anyone can check, nobody else can sign. Ethereum's cxSignRecoverable adds one byte from which cxRecover finds the signer's public key, so a message need not say who sent it; and Taproot's Schnorr signatures (cxSchnorrSign, cxSchnorrVerify) use the 32-byte x-only key:

Always compare a recovered key with the one you expected: any 65 bytes recover some key.

Transactions

A Bitcoin transaction spends earlier outputs and makes new ones. An input points at an earlier output, by its transaction's id and its number (cxBtcOutpoint); an output is an amount in satoshi, a hundred-millionth of a bitcoin, and the script that locks it (cxBtcOutput). cxBtcTxid gives the new transaction's id, the hash that names it on every block explorer:

CoinXT also builds and signs Ethereum payments (cxEth1559Sighash, cxEth1559Encode); the Dictionary has every handler, and Learn CoinXT (Help > Examples) walks through them.
