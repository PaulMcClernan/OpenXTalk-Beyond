Handlers for the whole program

A handler in a stack's script serves that stack's cards and controls (The message path). A library goes further: a stack whose handlers every script of the program can call, in any stack, as if they were built in. Text tools, a settings store, the code that talks to a server: anything several stacks need belongs in one.

When it is put into use, a library is sent libraryStack, and when it is taken out, releaseStack: the places to set it up and tidy it away. Other stacks' messages pass through a library too, so check that the message is the library's own:

Private helpers

Everything a library offers shares one name space with every other library and every script on the path, so a library should offer few names, and keep its helpers to itself. A handler marked private can be called only from its own script:

A script local such as sCount belongs to the library's script and lasts as long as the library is open, so it is a library's memory: settings, a cache, the connection it made.

Begin every public handler of a library with a short prefix of its own: ttShout and ttTrim for TextTools, say. Two libraries that both offer trimText cannot both be used, and the one further along the path is silently never called.

Front and back scripts

Any object's script can be inserted into the message path at either end. A front script sees every message before the object it is sent to: useful for logging, or for a tool that watches clicks. It should pass the message on, or it takes it away from everyone. The examples here make their buttons with create (Making controls from a script) and give them their scripts, so that each runs in one piece; in a stack of your own you would drag the buttons from the Tools palette and type the handlers into their scripts:

A back script sees a message only when nothing before it took the message: a place for what should happen when nothing else does.

the frontScripts and the backScripts list them. Libraries, back scripts and front scripts stay in place until they are removed or the program quits, so remove one when its work is done.

Try it yourself

Make a library Stats with a public function statsMean (the mean of a comma-separated list of numbers) and a private helper that adds the list up. Use it, put the mean of 4,8,15,16,23,42, show that the helper cannot be called from outside, and tidy up.
