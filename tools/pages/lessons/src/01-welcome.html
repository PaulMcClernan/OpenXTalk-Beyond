What is xTalk?

xTalk is a family of programming languages that read almost like English. It began in 1987 with HyperTalk, the language of Apple's HyperCard, which let teachers, artists and shopkeepers build their own programs. It lives on in LiveCode, OpenXTalk and OXT-Beyond, which is free and runs on Windows, macOS, Linux and in your browser.

Stacks, cards and scripts

An xTalk program is called a stack. A stack is a window, and it holds one or more cards, like a stack of index cards. On each card you place controls: buttons, text fields, pictures, menus and so on. You drag them onto the card from the Tools palette and arrange them with the mouse, much as you would in a drawing program, then set their colours, words and names in the Property Inspector. You do not need a line of code to lay out a window.

Every object, from a button to the stack itself, can have a script: the xTalk that says what it does. A button's script usually waits for a click:

When you click the button and let go, xTalk sends it the message mouseUp. The script has a handler for that message (everything from on mouseUp to end mouseUp), so its lines run: answer shows a little dialog with the words in quotes. You will meet handlers and messages properly in later lessons, and drag out a button and give it a script like this one in Stacks, cards and controls; for now, notice how readable it is.

A HyperCard stack from the 1990s used the same words: on mouseUp, answer, put. OXT-Beyond still understands them, and can even open old HyperCard stacks (File > Import Stack > HyperCard Stack).

Your first line

The first command most people learn is put. With nothing after it, put shows a value. Text goes inside double quotes; numbers do not need them.

The program runs from the top, one line at a time. Each line is one instruction, which xTalk calls a statement.

Where to run the examples

You can try every example in these lessons yourself, in OXT-Beyond. The bar on top of each one says where it goes:

  • Example: run it in the playground. Choose Help > xTalk Academy. The playground on the right of the window runs whatever you type when you press Run (or Ctrl+Enter), and shows every put on a line of its own in the Output, exactly as the lessons do. The first part of the course, about values, text and handlers, happens here.
  • Build it: your own stack. From the lesson Stacks, cards and controls on, you build a card of your own, the way most xTalk programs are made: choose File > New Stack > Default Size, drag controls from the Tools palette (Tools > Tools Palette) onto the card, and name them in the Property Inspector (double-click a control). A box marked Build it lists the steps.
  • Message Box: lines to type. Choose Tools > Message Box, type a line and press Return: it runs at once, on the card in front. A put shows its value there, and each one replaces the last, so these examples show what each put shows, in turn.
  • Script: what an object does. In Edit mode (the arrow at the top of the Tools palette), select the object and choose Object > Object Script, or right-click it and choose Edit Script. Paste the script and press Apply. Then click Run (the hand) at the top of the Tools palette, and click the object.

Nothing you type in the playground can harm your computer or your files, and the Academy keeps your work between visits. Experiment freely: change a number, run it again, see what happens. Save your own stack with File > Save to keep it.

How to read the lessons

Each example has a bar on top that says what it is, and a Copy button. Under it, Output shows exactly what the playground shows when you run it, and Message Box what the Message Box shows. The lessons are checked by running every example on the OXT-Beyond engine (on a card built as the steps say, for the ones on your own card), so what you see here is what you get.
