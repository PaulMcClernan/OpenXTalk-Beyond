Each handler has its own variables

A variable you create in a handler belongs to that handler alone. Other handlers cannot see it, and it is gone when the handler ends. Programmers call the part of a program where a name means something its scope.

In an ordinary script this is optional. But if you turn on Variable Checking in the Script Editor (Edit > Options > Variable Checking), xTalk insists that every variable is declared before it is used, and a mistyped name becomes an error you see straight away, rather than a word that quietly turns into text. The setting is called explicitVariables, and many experienced scripters keep it on.

Variables a whole script shares

Declare a variable with local outside any handler, at the top of the script, and every handler in that script can use it. It keeps its value between calls, for as long as the stack is open. These are called script locals, and many people start their names with s:

A script local is the natural home for something a button or card needs to remember: the score in a game, the file it opened last, whether it is busy.

Globals: one value for every script

A global is shared by every script in every open stack. Each handler that uses it must say so with global and its name, either inside the handler or at the top of the script:

A global nobody has put anything into is empty, and it lasts until you quit, even after the stack that made it closes.

Globals are easy to reach for and hard to live with: any script anywhere can change them, so when one holds the wrong value it is hard to find out who did it. Prefer parameters, script locals and, for what belongs to an object, custom properties, and keep globals for the few things that truly belong to the whole program. The g at the front of a global's name is a warning to every reader.

Constants: names that never change

A constant is a name for a value that stays the same while the program runs. Write it once, at the top, and use its name everywhere. When the value changes in a later version, you change one line.

The letters at the front

The names in these lessons follow a habit common across the xTalk world, which tells you where a variable lives without looking for its declaration:

  • t for a temporary variable inside one handler: tTotal
  • p for a parameter: pName
  • s for a script local: sCount
  • g for a global: gScore
  • k for a constant: kMaxLives

xTalk does not require any of this, but code that follows it is much easier to read, and it also keeps your names from colliding with xTalk's own words.
