Calling a handler by its name

Most of the time, what you want is not to run any code at all, but to call a handler whose name you work out as the program runs: the handler for a menu item, a command typed by the user, a step in a list. send and dispatch take the message as text, so the name can come from anywhere. dispatch leaves handled or unhandled in it, so a name with no handler is easy to spot:

For a function, dispatch function calls it with the parameters after with, and leaves what it returned in the result:

Prefer dispatch (Messages and events) to do whenever you can. The parameters go as values, so text with quotes or returns in it cannot break the call, and nothing but the handler you named can run.

Never run text you did not write

do, value and merge run whatever they are given, with all the power of your program: they can delete files, send data anywhere, or change any object. Never give them text that came from outside the program (a field the user typed in, a file, a web page) as it is. A calculator that works out what the user types must first make sure it is only a sum:

The pattern (Patterns) lets through only digits, the four signs of arithmetic, brackets, points and spaces, so nothing the user types can be a command. Check what is let in, not what is kept out: a list of forbidden words always misses one.
