A handler that calls itself

Some problems contain smaller copies of themselves. The factorial of 5 (5 × 4 × 3 × 2 × 1) is 5 times the factorial of 4; a folder holds files and smaller folders, which hold files and smaller folders. A handler can solve such a problem by calling itself on the smaller copy: this is recursion.

Every recursive handler has two parts: a base case, small enough to answer at once (pN <= 1), and a recursive case, which makes the problem smaller and calls itself. Each call has its own pN, so factorial(5) waits for factorial(4), which waits for factorial(3), down to the base case, and the answers come back up.

Thinking recursively

Recursion shines when the answer is easy to describe in terms of a smaller answer. The Tower of Hanoi moves a pile of disks from one peg to another, one disk at a time, never a big disk on a small one. Remembering answers

A recursive handler can do the same work many times. The Fibonacci numbers (each the sum of the two before) are a famous case: fib(30) worked out plainly calls itself well over a million times, mostly to work out the same few values again. Drawing with recursion

The examples in this lesson make their controls with create (Making controls from a script), so that each one runs in the playground in one piece. In a stack of your own you would drag the same controls from the Tools palette, name them in the Property Inspector, and put the handlers into their scripts: the code works the same either way.

A tree is a trunk with two smaller trees on top of it. Written that way, a few lines draw one: each call draws a branch, then calls itself twice for two shorter branches, turned left and right. One graphic holds every branch: in a graphic's points, an empty line lifts the pen, so the branches need not join up.

Nine levels of two calls each make 29 − 1 = 511 branches. Change the angle, the 0.75 or the depth, and the tree changes shape.

Everything recursion does, a loop can do too, with a list of the work still to do. A loop is the better choice when the depth could be huge (a folder tree made by a program, a list of a million items): the next lesson's search uses a loop and a queue.
