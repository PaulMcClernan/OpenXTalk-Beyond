A handler that gives a value

A command does a job. A function works out a value and gives it back, like the built-in round or max. You write one with function instead of on, and send the value back with return. To use it, write its name with brackets around the values, anywhere a value can go.

The brackets are what tell xTalk you are calling a function. They are needed even when there are no values to pass: pickColour().

A function with no return

If a function ends without a return, it gives back empty. That is rarely what you meant, so when a function's value looks blank, check that every path through it reaches a return.

Brackets or "the"

Many of xTalk's own functions have two spellings: length(tName) and the length of tName are the same call. Your own functions always use brackets.

Private handlers

Put private before function or command and the handler can only be called from the same script. It is a way of saying "this is a helper; nothing else should rely on it", and xTalk can also call it a little faster.
