Recipes that last

An algorithm is a recipe for a problem: steps that always reach the answer. Many of the best are old, and work the same in every language. This lesson writes a handful in xTalk, each a pattern you will meet again.

Euclid's algorithm

The greatest common divisor of two numbers, the biggest number that divides both, is what you need to simplify a fraction. Euclid wrote this method down around 300 BC: replace the pair by the smaller number and the remainder of dividing one by the other, until the remainder is 0.

The sieve of primes

To find every prime below a limit, do not test each number. The sieve of Eratosthenes crosses out the multiples of each prime as it finds it; whatever is not crossed out when you reach it is prime. An array marks the crossed-out numbers, and repeat with ... step counts through the multiples:

Searching: linear and binary

To find a value in a list, a linear search looks at each item in turn. In a list of 100,000 items, that can mean 100,000 looks. If the list is sorted, a binary search does far better: look at the middle item, and you know which half the value must be in; look at the middle of that half, and so on. Each look halves what is left, so 100,000 items take at most 17 looks.

The numbers are in an array, numbered from 1, not in lines of text. line 50000 of tList has to count 49,999 returns to find its line, every time, so a binary search over lines of text would lose most of its speed. split tList by return turns lines into such an array in one step (Arrays).

Stacks and queues

Two shapes of to-do list come up again and again. A stack is last in, first out, like a pile of plates: you add to the top and take from the top. A queue is first in, first out, like a line at a shop. With lines of text, both are a line or two:

An undo list is a stack: the last change made is the first undone. A list of files to download is a queue: the first asked for is the first fetched. The try-it below uses a stack; the maze uses a queue.

The shortest way through a maze

A breadth-first search finds the shortest path through a maze, a map or a network. Start with a queue holding the start. Take the first cell from the queue, and add each open neighbour not seen before, noting the cell it was reached from. Because the queue is first in, first out, cells are reached in order of distance, so the first time the search reaches the end, it got there by a shortest way. Following the notes back from the end gives the path.

The maze is lines of text, one character a cell, so a cell is a row and a column: char (column) of line (row). The search never needs to check for the edge of the map, because the map is walled all round. The path holds the cells between the start and the end, so the steps are one more than its lines.

Try it yourself

Use a stack to check brackets: go through the text a character at a time; push each opening bracket ( [ {; at each closing bracket, pop the last opening one and check that the two match. The brackets balance if nothing failed to match and the stack ends empty. Try (a[b]{c}), (a[b)] and ((.
