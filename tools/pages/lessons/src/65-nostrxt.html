A network of signed notes

Nostr is a social network with no company in the middle and no accounts. Everything on it is a short, signed piece of JSON called an event, and relays, servers anyone can run, keep events and pass them on. Because every event is signed, a reader can check who wrote it whichever relay it came from. NostrXT is the xTalk Suite's Nostr library, written in xTalk over CoinXT's signatures and SodiumXT's encryption; its handlers begin with nx.

The examples make keys from phrases, so that every run gives the same answers; a real app calls nxKeyGenerate() for a random one.

You are a key pair

On Nostr your secret key is 64 hex digits that only you hold, and your public key, which comes from it, is who you are to everyone. People share keys as npub names (and back them up as nsec names), which have a typo check built in:

An nsec is your secret key in another spelling: anyone who sees it can post as you, for ever. Never paste it into a website or a chat. NostrXT's nxUriEncode refuses to make a link to one.

Events, ids and signatures

An event has a kind (1 is a short note, 0 a profile, 7 a reaction), a time in seconds since 1970, its text, tags and its author. nxEventBuild makes one, and nxEventSign fills in the author, the id (the SHA-256 fingerprint of its exact text) and a Schnorr signature. nxEventVerify says true only when both check out, so treat anything else as fake:

The empty third parameter of nxEventSign asks for fresh randomness in the signature, so the same note signed twice has two different signatures, and both check.

On the wire: JSON

To travel, an event becomes JSON. nxEventToJson writes it, nxEventFromJson reads it back into an array, and nxJsonGet takes one value out by its name. Text from the internet could say anything, so verify what you read before you trust it:

Tags, replies and reactions

Tags label an event: "t" for a topic, "p" for a person mentioned, "e" for another event. nxTagsFromText makes them from text, a line each with a tab between the parts, and nxTagFirst and nxTagValues read them back. A conversation is events that point at each other with tags: nxReplyBuild makes a reply with an "e" tag for the post and a "p" tag for its author, and nxReactionBuild a reaction, kind 7, with "+" for a like:

A reply and a reaction come back unsigned, ready to sign with nxEventSign as any event.

Profiles and links

Your profile is an event too, of kind 0, with your name and a few words about you; post a new one to change it. nxMetadataBuild makes one, and nxMetadataParse reads it. To share a note, nxNeventEncode packs its id with a relay that has it, and nxUriEncode makes a nostr: link that apps open; nxEntityDecode reads any such name back:

Private messages

Notes are public. For a private message, NIP-44 locks it so that only one person can read it. nxNip44ConversationKey shows the trick: your secret key with their public key gives the same shared key as their secret key with yours, and it is never sent. nxNip44Encrypt locks a message for them, and nxNip44Decrypt opens it, or gives empty with the wrong keys:

Asking a relay

A relay answers filters: whose events, which kinds, how many. nxFilterBuild makes one from an array, and nxFilterMatches says whether an event fits, as a relay would decide. You talk to a relay in short JSON messages over a websocket: nxClientEvent publishes an event, nxClientReq asks with a filter under a name of your choice, and nxRelayParse reads the relay's answers, such as EOSE, "that is all, for now":

The nostr-relay library that comes with NostrXT opens the websockets and sends these for you; Learn NostrXT (Help > Examples) and the Dictionary have the rest, proof of work included.
