Name, number and id

You point at a control with the mouse. A script points at it with words, in three ways:

  • By name: button "OK", the name you gave it in the Property Inspector. Easy to read, and it survives moving the control about. Two controls can share a name, though, and then xTalk finds the first.
  • By number: button 2, or the last field. Handy in loops; it changes when controls are added, deleted or reordered.
  • By id: button id 1003. A number the engine gives each object when it is made, never reused in that stack, and never changed.
  1. On a new card, drag a Standard Button and name it OK.
create button "OK"
set the rect of it to 40,40,122,63

Type put the id of button "OK" to see its id: a number like 1003, which depends on how many objects the stack has made before.

Going through every control

Numbers make it easy to visit every control on a card. word 1 of the name of a control says what kind it is. This button lists every control on its card, itself included:

  1. On a new card, drag a Standard Button and name it Save.
  2. Drag a Field under it and name it Notes.
  3. Drag a Line Graphic (it keeps the palette's name, Line).
  4. Last, drag another Standard Button and name it List.
create button "Save"
set the rect of it to 40,40,122,63
create field "Notes"
set the rect of it to 40,80,140,101
create graphic "Line"
set the style of it to "line"
set the points of it to "40,130" & return & "160,130"
create button "List"
set the rect of it to 200,40,282,63

The loop collects a line for each control in a variable, and puts it once at the end, so the Message Box shows all four lines together. delete the last char takes off the return after the last line.

The long id: a reference you can keep

The long id of an object says exactly where it is: its id, its card's and its stack's. It is the most reliable reference there is, and since it is just text, you can keep it in a variable and use the variable wherever an object can go.

  1. On a new card, drag three Standard Buttons in a row and name them One, Two and Go.
create button "One"
set the rect of it to 40,40,122,63
create button "Two"
set the rect of it to 140,40,222,63
create button "Go"
set the rect of it to 240,40,322,63

That is what handlers usually pass to each other when they work on an object (and what it holds after create). To see one, type put the long id of button "One" in the Message Box. A reference you build yourself as text works the same way; put this in the script of the button Two:

Me, the target and the owner

Three words point at objects from where a script runs:

  • me is the object whose script is running. A button's mouseUp handler can set the label of me without knowing its own name, so the same script works in any button.
  • the target is the object a message was first sent to: the button that was clicked, even when the handler that runs is in the card's script (The message path).
  • the owner of an object is what holds it: a control's card (or its group), a card's stack.
  1. On a new card, drag two Standard Buttons and name them Red and Blue. Leave their scripts empty.
  2. Open the card's script with Object > Card Script.
create button "Red"
set the rect of it to 40,40,122,63
create button "Blue"
set the rect of it to 140,40,222,63

Neither button has a script of its own, so the mouseUp each click sends goes on to the card, whose script handles it. One handler serves every button, and the target tells them apart. (Click the card itself, away from the buttons, and it names the card.) The lesson The message path explains this journey.

Objects somewhere else

A reference with no card or stack means the current card of the current stack. Add of to reach further: field "Score" of card "Results", button 1 of card 3 of stack "Tools". You can read and set the properties of objects on any card of any open stack without going there.

  1. On a new card, drag a Field and name it Total.
  2. Choose Object > New Card. In the Card Inspector (Object > Card Inspector) name the new card Results, then drag a Field onto it and name it Score.
  3. Go back to the first card with View > Go Prev.
create field "Total"
set the rect of it to 40,40,140,61
create card "Results"
create field "Score"
set the rect of it to 40,40,140,61
go to card 1

The first card has one field; the 42 went to the other card's field without leaving this one. Choose View > Go Next to see it there.

Try it yourself

On a new card, drag four Standard Buttons and name them Red, Green, Blue and Go. Give Go a script that, in a loop over the number of buttons, sets each button's label to its name in capitals, and then puts the labels, with commas between them.

  1. Drag four Standard Buttons in a row and name them Red, Green, Blue and Go.
repeat with i = 1 to 4
   create button (item i of "Red,Green,Blue,Go")
   set the rect of it to i * 100 - 60, 40, i * 100 + 22, 63
end repeat
